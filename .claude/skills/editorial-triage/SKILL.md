Consumes the output of an editorial review (the saved run record of the `editorial-review` workflow, or a directory of v2 findings files) and closes every finding with one move. The deterministic work (normalise, resolve anchors, gate rewrites, dedup, plan, apply) lives in `build-triage.sh` and `grade-triage.sh`; the judgment work (predicting the closing move for each cluster from the rubric) fans out to one `GRADER` per page. The outcome is written to `~/trade-imports-arch-workspace/.claude/workareas/editorial-triage/<run>/`: `calibration/grades/*.json` and `calibration/score.json`, then `closing/plan.md` (the report), `closing/plan.json` and, after the apply step, `closing/applied.json`. The pages change only in the apply step, in the docs working tree, and are never committed here.

**Bash call hygiene** - one command per Bash call; paths in the literal `~/trade-imports-arch-workspace/...` form. Full rules: [`agent-skills.md`](../../best-practices/skills/agent-skills.md).

The frame is closing, not opening. Every finding gets exactly one closing move: `R` remove, `C` correct, `W` reword, `K` keep one side, `O` record as open with an owner, `I` ignore for now, `T` tell me what to do. Removal is tried first, growth needs a heuristic that allows the growth, and no question is put to the user in chat. The rubric that defines the moves: [`assets/grading-rubric.md`](assets/grading-rubric.md). The record contract and every rule the helpers apply: [`assets/editorial-triage-schema.md`](assets/editorial-triage-schema.md).

## When to use

| Trigger | What to follow |
|---------|----------------|
| "triage the review", "triage the editorial review", "close the review" | Steps 1 to 8 on the review's run record |
| "triage findings" | Steps 1 to 8 on a findings directory (`--from-review`) |
| "editorial triage" | Steps 1 to 8; ask which run if none is named |

NOT for producing the findings (run the `editorial-review` workflow first), for writing or revising the prose (the `editorial` skill), for committing (the user commits the diff), or for publishing (`confluence-publish`).

## State

Canonical state is JSON under `~/trade-imports-arch-workspace/.claude/workareas/editorial-triage/<run>/` (gitignored): `findings.json`, `triage.json`, `index.json`, `manifest.json`, `calibration/` and `closing/`. Schema and rules: `assets/editorial-triage-schema.md`. Mutated only by the helpers (atomic write, then mv). The markdown views (`closing/plan.md`, `calibration/round-<n>.md`) are regenerated by the helpers; never hand-edit them.

## Step 1: Name the run and its inputs

Establish: the review to triage (a run id such as `wf_f07b54c5-79b`, a run record path, or a directory holding `review/*.json`); the state of the pages the reviewers read (`git -C <docs repo> status --short` shows uncommitted edits; pass `--commit` a label such as `e7cbdb0+edits` when the tree is dirty, so the manifest says what was reviewed); and a run slug for the workarea, `<docset>-<date>` (for example `ins-auth-2026-09-10`).

## Step 2: Build

```
bash ~/trade-imports-arch-workspace/.claude/tools/editorial-triage/build-triage.sh --from-run <run id or path> --dir ~/trade-imports-arch-workspace/.claude/workareas/editorial-triage/<run> --commit <label>
```

Read the summary lines it prints: records by source, clusters and duplicates collapsed, anchor rungs, buckets. A v2 result (the workflow returns `version: 2`) builds without a legacy flag; if the build reports a legacy result (buckets all `unclassified`), go to Step 3, otherwise to Step 4. A build that stops with a message names the remedy (missing page, missing run record). The buckets only stratify the calibration sample; the closing move comes from the grader.

## Step 3: Backfill a pre-v2 review (once)

Spawn one `LEGACY_CLASSIFIER` per page listed in `manifest.json`, plus one with page `set` when `findings.json` holds records whose page is `set`, all in one message. Wait for every worker's one-line return. Then run the Step 2 build again; the classified files are picked up automatically. Classified files are frozen after this step.

## Step 4: Grade

Spawn one `GRADER` per page in `manifest.json`, plus one with items `set` when `triage.json` holds set-wide clusters, mode `seen`, all in one message. Each grader reads the rubric, the page and every cluster on that page, predicts the move with a heuristic id and one gated sentence, and writes `calibration/grades/<page>.json`. Wait for every one-line return and check the counts add up to the page's clusters.

## Step 5: Score

```
bash ~/trade-imports-arch-workspace/.claude/tools/editorial-triage/grade-triage.sh score --dir ~/trade-imports-arch-workspace/.claude/workareas/editorial-triage/<run>
```

The score is the share closed without the user (`R`, `C`, `W`), the load (`K`, `O`, `T`) and the share ignored, overall and per page. When the same document set was scored before, compare the two: fewer findings, a higher closed share and a lower load say the review upstream improved; the reverse says the rubric or the brief needs work before anything is applied.

## Step 6: Plan and spot check

```
bash ~/trade-imports-arch-workspace/.claude/tools/editorial-triage/grade-triage.sh plan --dir ~/trade-imports-arch-workspace/.claude/workareas/editorial-triage/<run> --sample 10
```

`closing/plan.md` is the report: Apply (`R`, `C`, `W` with the text each edit needs), Decide (`K` with both statements and the default side; `T` with the instruction needed), Open (`O` lines with owners), Ignored (a count) and Problems (clusters the plan cannot close, with the reason). Show the user the Spot check section verbatim: ten apply entries with before and after. One veto halts the batch. Turn the veto into a rubric heuristic through the Calibrate loop below, re-grade the page it came from, re-plan with a new `--seed`, and spot-check again. Zero vetoes releases the batch.

## Step 7: Apply

```
bash ~/trade-imports-arch-workspace/.claude/tools/editorial-triage/grade-triage.sh apply --dir ~/trade-imports-arch-workspace/.claude/workareas/editorial-triage/<run> --dry-run
```

The dry run lists what would apply and what skips (a phrase absent from the page, or present more than once). Then apply for real, adding `--force` only when the user has said the working tree's uncommitted edits under the pages are theirs. Never add `--no-spot-check`: that flag turns off the refusal that Step 6 exists to arm, and the user's approval of the spot check is what licenses this step.

```
bash ~/trade-imports-arch-workspace/.claude/tools/editorial-triage/grade-triage.sh apply --dir ~/trade-imports-arch-workspace/.claude/workareas/editorial-triage/<run>
```

Each changed page runs the prose gate; an entry on a failing page carries `gate-fail` and the exit code is 2. Run the docs repo's own validation next (the command its CLAUDE.md names), then show the user `git diff --stat` and the diff. Never commit; the user commits.

## Step 8: Present what is left

Show the user the Decide and Open sections of `closing/plan.md` verbatim, then the Ignored count and the Problems list. A `K` or `T` answer is an edit the `editorial` skill makes by hand, since the apply step covers `R`, `C` and `W` only; an `O` line goes to its owner outside this skill. Finish with one cold-reader pass over the changed pages, as the `editorial` skill's review path describes.

## Calibrate: build the grader from walked samples

Run this before tuning rules or changing the review upstream, and whenever the user's verdict on a run is "too much" or "not sure it is right". The grader is the shared definition of how a finding is closed; the rubric holds that definition. Rubric: `assets/grading-rubric.md`. Worker: `references/GRADER.md`.

1. Draw a round of ten items, evenly across the tool's categories, from a built run:

```
bash ~/trade-imports-arch-workspace/.claude/tools/editorial-triage/grade-triage.sh sample --dir ~/trade-imports-arch-workspace/.claude/workareas/editorial-triage/<run> --round <n> --size 10
```

2. Show the user the cards in `calibration/round-<n>.md` verbatim. From round 2 onward, spawn a `GRADER` first in `blind` mode on the round, so the round is unseen when the grader grades.
3. Take one entry per card from the user: the card number, one closing move (`R` remove, `C` correct, `W` reword, `K` keep one side as `K:A` or `K:B`, `O` record as open with an owner, `I` ignore for now, `T` tell me what to do, which needs the instruction as its note) and an optional note in their words, for example `2 R; 3 R cut the mechanism, keep the requirement; 10 O`. A `T` instruction and every note become candidate heuristics. Record them:

```
bash ~/trade-imports-arch-workspace/.claude/tools/editorial-triage/grade-triage.sh label --dir ~/trade-imports-arch-workspace/.claude/workareas/editorial-triage/<run> --round <n> --labels "<entries>"
```

4. Measure agreement between the grader and the user on the round, and read the disagreements:

```
bash ~/trade-imports-arch-workspace/.claude/tools/editorial-triage/grade-triage.sh agree --dir ~/trade-imports-arch-workspace/.claude/workareas/editorial-triage/<run> --round <n>
```

5. Turn each disagreement, and each note, into a rubric heuristic (`H-<nn>`, with the items that produced it) in `assets/grading-rubric.md`. A heuristic must hold for any technical document; a rule that only fits the document set under review is a run note for the review workflow, not a rubric entry. In round 1 the grader runs after the labels, to check the first rubric; in later rounds it runs blind before them.
6. Stop when two consecutive rounds reach move agreement of at least 0.85, or when the user says the heuristics are settled. Then grade and score the whole run (Steps 4 and 5); that score is the baseline every later change to the rules or the review brief is measured against. Nothing in the pages changes during calibration.

## Scripts cheat-sheet

All under `~/trade-imports-arch-workspace/.claude/tools/editorial-triage/`:

| Script | Purpose |
|---|---|
| `build-triage.sh` | Normalise a review result (v2 through `lib/normalize-v2.jq`, pre-v2 through `lib/normalize-legacy.jq` plus the classifier) into records, resolve anchors, gate rewrites, cluster, partition and rank |
| `grade-triage.sh` | Calibration: `sample` a round of clusters as cards, `label` the user's move per card, `agree` the grader against the labels, `score` a whole run. Closing: `plan` the move that closes each cluster with a spot check, `apply` the R, C and W entries to the pages (`--dry-run`, `--moves`, `--force` for a dirty tree, `--no-spot-check` which the skill never passes) |
